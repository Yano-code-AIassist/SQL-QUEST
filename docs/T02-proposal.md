## SQL実行条件案

| 項目 | 提案 |
| --- | --- |
| 実行場所 | UIとは別のWeb Worker内、学習用のメモリーDBのみ |
| プレイヤーが実行できるSQL | SELECT、INSERT、UPDATE、DELETE |
| 文数 | 1回につき1文。空入力と複数文は実行前にエラー |
| その他のSQL | CREATE/DROP/ALTER、PRAGMA、ATTACH、トランザクション制御などはMVPでは受け付けない。初期DB作成の内部SQLとは区別する |
| 初期化 | 問題の開始・切替・リセット時に初期データから再作成する |
| 同じ問題での再実行 | 直前までの変更を保持。最初からやり直す場合はリセット |
| SQLエラー | その実行で行った変更だけを取り消し、直前の正常な状態を保つ |
| SQL実行の制限時間 | 1回5秒。超過時はWorkerを終了し、その問題を初期状態に戻す |
| 初回読み込みの制限時間 | sql.jsとDBの準備には別途15秒。SQLの5秒には読み込み時間を含めない |
| SQLエラー応答 | 成功/失敗、種別、元のSQLエラーを返す。UIの詳しい説明文はT20 |
| DBの保存 | DB自体は永続保存しない。学習進捗のLocalStorage保存はT18 |

文の区切りは引用文字列やコメント内のセミコロンと区別する。単純なセミコロン分割だけで判定しない。
タイムアウト時に失われるのは、その問題の一時DBの変更。将来の学習進捗保存とは分離する。

## 応答と責務

- SQLエンジン: 初期データからDBを作成し、列名・行データ・変更行数を返す。
- Worker: 初期化・実行・終了のメッセージを受け、要求IDと結果を対応させる。
- 呼び出し側: 制限時間を管理し、異常時にWorkerを終了する。
- UI: 実行完了またはエラーを表示する。採点結果はこの段階では返さない。

## 検証計画

| ケース | 期待結果 |
| --- | --- |
| SELECT * FROM adventurers | 上記5行と3列が返る |
| レベル10以上のmonstersを取得 | ドラゴンとオークが返る |
| INSERT/UPDATE/DELETE | 変更後のデータ状態が想定どおり |
| 重複IDのINSERT・SQL構文エラー | エラーが返り、元の正常なデータを保つ |
| 0件のSELECT | 行なしの結果を正しく扱う |
| 空入力・複数文・対象外SQL | 対象外として実行しない |
| 問題ごとの初期化 | 他の問題のDBに変更が伝わらない |
| タイムアウト | Workerを停止し、UIが応答可能で、再初期化して再試行できる |
| 再読み込み | 一時DBが初期状態に戻る |

本実装では型チェック・ビルドと自動テストを行い、ブラウザーで本物のWeb Workerが動くことを手動確認の対象にする。
モックの成功をブラウザー実動作の成功として報告しない。
